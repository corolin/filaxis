# 技能剧本：跨主机网络诊断

> 场景：一个终点不通/变慢，需要在多台机器上协同取证（抓包 + 探测 + 日志对照），定位问题发生在哪一段。面向 Agent 或工程师，照步走。
> 体量 ~0.8K tokens · **何时不用**：单机内就能定位的问题（先在本机层排查完再上多机）；纯配置错误不需要网络取证。

## 剧本

1. **建层（两个独立长连接，互不影响）**：一端在防火墙/路由器（有抓包权），另一端在受害源主机。两端各 connect 一个层。
2. **先抓包后探测（就绪握手是关键）**：在防火墙层 spawn 抓包任务后，**必须等就绪标记**再从源主机发起探测——`exec 返回 ≠ 抓包已开始监听`，跳过握手是本场景最经典的竞态。
3. **探测带超时与退出码判定**：TCP 探测命令显式超时；结果按退出码分支（退出码是数据），不要因非零就中断剧本。
4. **收尾顺序**：等抓包任务自然终态（计数满退出）→ 取退出码 → 拉回 pcap/日志 → 逐层销毁。
5. **分段定责**：源侧 RST / 防火墙侧丢包 / 目标侧无 SYN——三段证据对照给结论，缺一段就明说缺。

## 陷阱清单

- **ssh-config 别名的环境依赖**：`--host`/`-J` 传别名时，解析用的是**本运行环境**的 `~/.ssh/config`——你在沙箱/远端会话里跑 filaxis 时，本机有的别名那边没有（连接层报错会带此提示）。跨环境一律 `user@host[:port]` 字面量，或先在运行环境补 config；跳板拓扑也可用「直连可达层 + 内网嵌套派生（sshInto/--hop）」替代 `-J`。
- **BSD 防火墙**（OPNsense/pfSense）：`tcpdump -i any` 不可靠——按网卡分别抓；`base64 -w 0` 这类 GNU 参数在 BSD 上会报错（方言探测自动处理，你的自定义命令要自己防）。
- 抓包文件用**文件传输 API**拉回（带 sha256 校验），不要 `cat` 二进制进 stdout。
- 若中途连接断开，任务终态可能是 `unknown`——重连后先核实（进程是否真的还在），再决定杀或接。

## 适用层

任何可达层：SSH 主机、防火墙（SSH 可达）、容器。环境能力（有无 tcpdump/nmap）先探测再选层——别在不存在的工具上空转。
